# Version Snapshot Schema

**Status:** Reviewed
**Primary files:** `lib/sync-service/version-snapshot.ts`, `lib/sync-service/publish-transaction.ts`, `lib/persistence/indexeddb-adapter.ts`

## Overview

A **VersionSnapshot** is a durable record of one publish *attempt*. It carries enough information to:

- show "what was published, when, by whom" in Version History
- compute a workspace-level diff between two snapshots without re-running the publish pipeline
- restore a historical workspace into a fresh draft (Phase 3)
- audit publish outcomes per release target

A **RestoreEvent** is a sibling, append-only audit row that records each Restore-to-Draft action against a snapshot. The two records together form the durable shape of release history in Hiero.

## Goals

- One snapshot per publish *attempt* — not per release target
- Snapshot persists when **at least one** target succeeds (partial failure is captured, not lost)
- All-target failure produces no snapshot — the user retries from the dialog
- Restore audit can never be silently rewritten (no `deleteRestoreEvent` API)

## Non-Goals

- This is **not** the snapshot artifact published to npm or pushed via PR — those are produced by the existing `lib/sync-service` transports. VersionSnapshot is the **record** of that publish, not its payload.
- VersionSnapshot does not replace `DraftCheckpoint` — checkpoints are local-only intent; snapshots are post-release records.
- No two-phase commit across heterogeneous remotes (GitHub + npm + filesystem). Partial failure is a first-class outcome, not a bug.

## Types

```typescript
export type ReleaseTargetKind = 'local-directory' | 'git-pr' | 'npm-registry';
export type TargetResultStatus = 'success' | 'failed';

export type TargetResult = {
  kind: ReleaseTargetKind;
  status: TargetResultStatus;
  url?: string;          // PR URL, npm package URL, local path — required on success
  timestamp: string;     // ISO
  error?: string;        // failure reason — never set on success
};

export type ChangesSummary = {
  added: string[];
  modified: string[];
  removed: string[];
};

export type VersionSnapshot = {
  id: string;
  version: string;             // semver string, not validated at write time
  releaseNotes: string;
  publishedAt: string;         // ISO
  publishedBy: string;
  changesSummary: ChangesSummary;
  sourceHash: string;          // FNV-1a hex of JSON.stringify(workspace) — non-cryptographic
  targetResults: TargetResult[];
  workspaceSnapshot: Workspace;
};

/** Lightweight metadata view for list UIs that don't need the workspace payload. */
export type VersionSnapshotMeta = Omit<VersionSnapshot, 'workspaceSnapshot'>;

/** Append-only audit record for restore actions. */
export type RestoreEvent = {
  id: string;
  snapshotId: string;
  snapshotVersion: string;       // denormalized for read speed
  restoredAt: string;            // ISO
  restoredBy: string;
  projectId: string | null;      // null when restored without a project context
  preservedDirtyWorkAs: 'checkpoint' | 'discarded' | 'no-dirty-work';
};
```

## Persistence rules

- Snapshots are written via `PersistenceAdapter.saveVersionSnapshot` — uses `put` (id is unique, generated by the publish transaction).
- Restore events are written via `appendRestoreEvent` — uses `add` (not `put`) so duplicate ids throw. There is **no** `deleteRestoreEvent` method on the interface.
- Each snapshot embeds the full `Workspace` so Restore can reconstitute the published state without depending on whether the original release artifact (PR, npm publish, local snapshot) is still reachable.

## IndexedDB layout

- Schema versions: 3 (snapshots, Phase 2) and 4 (restore events, Phase 3)
- Stores:
  - `hiero_version_snapshots`, `keyPath: 'id'`, index `publishedAt` for chronological listing
  - `hiero_restore_events`, `keyPath: 'id'`, compound index `snapshotId_restoredAt` on `['snapshotId', 'restoredAt']`
- Both upgrades fall through cumulatively from earlier versions — see `lib/persistence/indexeddb-adapter.ts:applyUpgrade`.

## sourceHash

Deterministic FNV-1a 32-bit hex over `JSON.stringify(workspace)`:

- Used by Compare to short-circuit identical-source diffs
- Non-cryptographic — only intended for change detection and stable identity in caching
- See `hashWorkspace` in `lib/sync-service/publish-transaction.ts`

## Storage model summary

```text
DraftCheckpoint (Phase 1)        VersionSnapshot (Phase 2)        RestoreEvent (Phase 3)
─────────────────────────        ──────────────────────────        ──────────────────────
hiero_draft_checkpoints          hiero_version_snapshots           hiero_restore_events
keyPath: id                      keyPath: id                       keyPath: id
indexed by projectId+createdAt   indexed by publishedAt            indexed by snapshotId+restoredAt
mutable (delete supported)       append-only writes                append-only (no delete API)
```

## Test contract

- `tests/publish-transaction.test.ts` — snapshot persisted on any-success; not persisted on all-fail; targetResults preserve order
- `tests/restore-to-draft.test.ts` — RestoreEvent written per restore; never silently publishes; missing snapshot id throws; multiple restores of same snapshot accumulate
- `tests/idb-migration.test.ts` — v2→v3, v3→v4 upgrade hops + fresh install land at the same final schema
